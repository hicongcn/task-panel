# 安全设计

本文件记录 MVP 已落实的安全措施,以及从同类项目审计中吸取并主动规避的已知问题。

## 已落实

### 命令执行
- 任务命令 **100% 参数化构造**(`exec.Command` + 显式 args),禁止 `sh -c` 拼接用户输入。
- 命令解析器只接受"解释器 + 脚本路径 + 参数"白名单格式,脚本路径必须存在且位于脚本目录内。

### 路径安全
- 所有文件读写走 `pkg/pathutil`:归一化 → 拒绝绝对路径 / `..` / 盘符 → 解析符号链接后校验仍在基础目录内。
- 同时解析 **base 自身的软链**(如 macOS `/tmp`→`/private/tmp`),避免 base 与 target 解析不一致导致的误判与绕过。
- 上传:文件大小上限 + 扩展名白名单 + `filepath.Base` 取基名。

### 鉴权与会话
- 密码 bcrypt;JWT 密钥随机生成、持久化 0600、留空时不回退到弱默认。
- 登录失败锁定(5 次 / 15 分钟,阶梯延长)+ 每 IP 限流。
- 登出 / 改密按 jti 进黑名单,令牌可即时作废。
- 首次初始化接口 `NeedInit()` 守卫,管理员创建后即关闭。

### 客户端 IP 解析(吸取参考项目教训)
- **默认只信任回环地址**(127.0.0.1/32、::1/128),**不默认信任整个 RFC1918 私网段**。
- 原因:局域网直连(无反代)部署下,若默认信任私网段,攻击者可伪造 `X-Forwarded-For` 绕过登录限流与 IP 白名单。
- 部署在反向代理后时,管理员显式配置 `TRUSTED_PROXY_CIDRS` 为代理网段。

### IP 白名单(v0.3)
- 可选访问白名单(`security.ip_whitelist` / `IP_WHITELIST`):逗号分隔的单个 IP 或 CIDR。
- 中间件位于路由最前端,基于**解析后的真实客户端 IP**(走可信代理逻辑,防伪造)校验;不在名单内一律 403。
- 留空表示不启用,默认行为不变。

### CORS
- 仅放行显式配置的 origin,**拒绝 `null` / 空 origin**(避免 sandbox iframe 等场景的宽松放行)。
- MVP 不使用 Cookie 凭据,`AllowCredentials: false`。

### 日志渲染(XSS)
- 前端 `ansi → HTML` 前,**所有文本段先经 `escapeHtml`**,再按颜色码包 `<span>`,杜绝日志注入脚本。

### 下载鉴权
- 浏览器原生下载无法带 Authorization,改用短期 HMAC 票据(`pkg/dlticket`):绑定资源 + 纳秒级过期 + 签名校验 + 防篡改。

### 实时日志(SSE)鉴权
- `EventSource` 同样无法带 Authorization,但 **不直接把 JWT 放 query**(会泄漏到访问日志/浏览器历史)。
- 改为:先经鉴权接口 `GET /tasks/:id/live-ticket` 换取短期 HMAC 票据(绑定任务 ID、10 分钟有效),再以票据建立 SSE 连接。
- 访问日志对 `token`/`ticket` query 参数统一脱敏。

### 资源限制
- API 请求体上限 100MB(`http.MaxBytesReader`,含备份恢复上传),脚本内容单文件上限 10MB,防止超大请求耗尽内存。

### 2FA / TOTP(v1.0)
- 标准 RFC 6238 TOTP(6 位、30 秒窗口、±1 窗口容差),实现仅用标准库并有 RFC 官方测试向量校验。
- 启用:服务端生成 base32 密钥 → otpauth URI → 前端渲染二维码扫码绑定 → 输入动态码确认。
- 登录:已启用 2FA 的用户必须提供动态码,错误计入登录失败锁定。
- 兜底恢复:CLI `account-reset --user admin --disable-2fa`(丢失验证器时唯一找回通道)。

### 依赖管理(v0.3)
- pip / npm 命令一律**参数化构造**(`exec.Command` 显式 args,不经过 shell)。
- 包名做**字符白名单校验**(仅 `字母数字._-=<>~[],+`,拒绝空白/控制字符/元字符),长度上限 200。
- 安装/卸载**串行执行**(全局互斥),避免系统级并发互扰;命令输出截断 200KB 返回。
- 操作记录审计日志(dep_install / dep_uninstall)。
